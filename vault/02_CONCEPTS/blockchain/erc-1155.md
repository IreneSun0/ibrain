# ERC-1155 | 多代币标准

## Executive Definition / Chinese Explanation | 定义与解释

**ERC-1155 | 多代币标准** = 一个合约里可以有无数个 token id，**id 之间异质（各代表不同东西），id 之内同质（每一份完全等价可互换）**，并且支持批量转移。

它是 [[erc-20]] 和 [[erc-721]] 的合体：**721 的"多个不同东西" + 20 的"每种可分割互换"。**

## Why This Matters | 为什么重要

**它正好是事件市场需要的形状**，这不是巧合 —— 条件代币框架就是围绕它设计的：

- 一个平台有上万个市场 → 需要"一个合约容纳多个 id"。
- 每个市场有多个结果 → id 之间必须异质。
- 同一结果的每一份必须等价可互换 → id 之内必须同质。
- 铸造/合并要同时操作 YES 和 NO → **需要批量转移。**

**四条要求，ERC-1155 全部满足，其他标准都缺至少一条。**

## How It Works | 机制怎么运转

在事件市场里，一个 token id 通常由这样一组信息哈希得出：

```
token id = hash(条件 id, 结果索引, 抵押品地址)
  ├─ 条件 id     = 该市场的唯一标识（含预言机、问题、结果数）
  ├─ 结果索引    = YES=0 / NO=1（或多结果的 0..N-1）
  └─ 抵押品地址  = 用什么资产抵押（如 USDC）
```

**这个设计有一个重要后果**：同一个问题、不同抵押品的合约，是**不同的 token id**，因此不可互换。这在跨平台聚合时是一个必须处理的细节 —— 它也是 [[canonical-event-id]] 这类主键设计要面对的问题之一。

## Concrete Example | 具体例子

一个三选一市场在链上的完整形态：

```
合约地址 0xABC…（条件代币）
 ├─ id 0x1f3a…  = "候选人 A 当选"   持有 1,200 份
 ├─ id 0x9c72…  = "候选人 B 当选"   持有   800 份
 └─ id 0x4e01…  = "其他/无人当选"   持有    50 份
```

**铸造**：存 $1 → 三个 id 各得 1 份（完备集）。
**合并**：交回三个 id 各 1 份 → 取回 $1。
**批量转移**：一次交易把三个 id 的持仓全部转出 —— **ERC-20 方案需要三次交易。**

**"批量"在这里不是优化，是可用性**：一个套利者要同时操作完备集，逐个转账的 gas 成本会让套利本身不划算。

## Common Misconceptions | 常见误解

- **误解一："ERC-1155 就是'半同质代币'。"** 更准确的说法是**"多品类代币"**：每个 id 内部完全同质，只是一个合约能装多个品类。
- **误解二："用了 1155 就自动可组合。"** 还要看 DeFi 协议支不支持 1155 —— **很多老协议只支持 ERC-20**，这是事件敞口进入 DeFi 的实际障碍。
- **误解三："id 相同就是同一个市场。"** id 由条件 + 结果 + 抵押品共同决定，**换抵押品就是不同的 id。**

## In Practice | 实战里怎么用

分析一个链上事件市场的持仓，三步：

1. **拿到合约地址** —— 通常在平台文档或区块浏览器上可查。
2. **解析 token id** —— 反查它对应哪个条件、哪个结果、哪种抵押品。
3. **按地址聚合** —— 得到持仓分布、集中度、建仓时序。

**这三步做完，你就能独立完成传统市场里需要监管权限才能做的分析**（见 [[on-chain]]）：谁持有多少、什么时候建的仓、在什么消息之前。

**注意第 2 步的陷阱**：不同抵押品的同一问题是不同 id，聚合时要合并。

## Active-Recall Questions | 主动回忆题

- Q: ERC-1155 的核心结构是什么？
  A: 一个合约容纳多个 token id，id 之间异质（代表不同结果），id 之内同质（每份等价可互换），并支持批量转移。
- Q: 事件市场对代币标准的四条要求是什么？
  A: 一个合约容纳多个市场、id 间异质、id 内同质可互换、支持批量转移（铸造/合并要同时操作多个结果）。
- Q: 为什么同一个问题、不同抵押品的合约是不同的 token id？
  A: id 由条件 id、结果索引和抵押品地址共同哈希得出，换抵押品即换 id，跨平台聚合时必须处理这个细节。
